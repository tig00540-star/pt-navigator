# 계획서 — 구독 해지 · 개인 → 센터 합류 · 센터 → 개인 독립 (2026-10-06)

> 대표 결정 대기 항목은 **[결정]** 으로 표시. 구현 전에 이 문서로 확정한다.

## 0. 왜

| 상황 | 지금 일어나는 일 | 잃는 것 |
|---|---|---|
| 센터가 구독을 끊음 | 대표 · 트레이너 모두 잠김 · **회원 페이지도 바로 닫힘** · 기록 접근 불가 | 트레이너가 회원 · 기록을 전부 잃음 → 개인 고객으로 남을 이유가 없음 |
| 트레이너가 센터를 나가 혼자 운영 | 같은 이메일로 개인 가입 불가 · 새 계정은 빈 상태 | 위와 같음 |
| 개인으로 쓰던 트레이너가 센터에 들어감(또는 그 센터가 센터 요금제 시작) | 센터 계정으로 옮길 방법 없음 · 이중 결제 | "혼자 써 보고 좋으면 센터로" 영업 흐름이 막힘 |
| 고객이 그만 쓰고 싶음 | **해지 화면이 없음**(랜딩엔 "언제든 해지") | 신뢰 · 법적 리스크 |

## 1. 단계

1. **해지 · 30일 읽기 전용 · 내보내기** — 모든 계정에 필요. 아래 2 · 3의 바탕(해지 뒤 30일 안에 독립을 할 수 있어야 함).
2. **이동 코어**(회원 · 기록을 계정 A → B로 옮기는 서버 함수 하나) + **개인 → 센터 합류** 화면.
3. **센터 → 개인 독립** 화면(같은 코어).
4. **포인트**(남은 개인 구독 기간 → 적립금 → 다음 결제 할인).

작업 크기: 1 = 하루 · 2 = 이틀 · 3 = 하루 · 4 = 반나절(+ 결제 작업 수정).

## 2. 해지 · 30일 읽기 전용 · 내보내기

**화면(대표 · 개인 계정 주인만):** 설정 › 내 정보 › **구독**
- 지금 요금제 · 다음 결제일 · 카드 끝 4자리(있으면) · 포인트(4단계 뒤)
- **[해지 예약]** → 확인 창("○월 ○일까지 그대로 쓰고, 그 뒤 30일 동안 볼 수만 있어요. 그다음 기록이 지워져요.") → `cancel_at_period_end = true`
- 예약 중엔 **[해지 취소]** · 카드 변경(토스 빌링 재등록)
- 쓰기는 서버 라우트(`/api/billing/cancel`)만 — account UPDATE 정책은 열지 않는다(기존 원칙).

**기간이 끝나면(결제 작업이 이미 inactive로 바꿈):**
- 지금: 바로 결제벽. → **바꿈:** 끝난 뒤 **30일은 읽기 전용**(로그인 · 열람 · 내보내기 · 독립 신청만 · 새 기록 · AI 없음).
  - DB: `account.read_only_until`(기간 끝 + 30일) · 접근 함수 `my_account_status()`에 `mode: 'full' | 'read_only' | 'locked'` 추가 · 쓰기 정책들이 쓰는 게이트(`auth_account_id()` 계열)는 read_only면 쓰기 거절.
  - 회원 페이지: 30일 동안 **볼 수만** 있게(지난 회원 읽기 전용과 같은 화면 재사용) · 그 뒤 닫힘.
- 30일 뒤: 파기 작업(예약 작업 · 약관 11조 '해지 30일 파기') — 회원 · 기록 · 사진 · 서명 그림 · 사례 파일까지. 파기 전날 대표 알림.

**내보내기:** [내 데이터 내려받기] → 회원 목록 · 계약 · 수업(운동일지) · 인바디 · 장부를 **엑셀(CSV) 묶음 ZIP**. 사진 · 서명 그림은 링크 목록. (지금 '사본 제공은 수동'인 약관 문구를 이걸로 대체)

**[결정]** 30일 읽기 전용이 맞는지(약관 11조와 일치) · 파기 전에 한 번 더 묻는 알림을 보낼지.

## 3. 이동 코어 (합류 · 독립 공용)

`move_members(from_account, to_account, trainer_id, member_ids[], mode)` — 서버 라우트(service_role) 한 곳에서, 한 트랜잭션(DB 함수)으로.

**옮기는 것(회원 단위 · account_id 바꿈):**
`user_table` · `ot_log` · `session_log`(계약) · `daily_workout_log` · `workout_log_confirmation` · `workout_log_signature` · `inbody_log` · `appointment` · `appt_request` · `member_consent` · `member_photo` · `cardio_log` · `schedule_check` · `member_routine` · `member_routine_log` · `member_routine_request` · `member_roadmap` · `member_event_join`(이벤트는 안 옮김 → 참여 기록만 끊음) · `owner_feedback`(안 옮김 · 센터 것) · `push_subscription`(회원 기기 → 따라감)

**트레이너 것(같이 가는 것):** `pt_package`(본인 가격표) · `sales_case`(본인 사례 + 저장소 `sales-cases/{계정}/…` 파일 복사) · `trainer_profile` · `library_item` · `notify_pref` · `intake_link`(본인 QR → 새 계정으로 · 코드 그대로라 이미 뿌린 QR도 계속 됨)

**저장소:**
- 회원 사진 `member-photos/{회원}/…` — 회원 기준 경로라 **그대로**(정책이 회원의 계정을 보므로 따라옴 · 확인 필요).
- 서명 그림 `log-signatures/{계정}/{회원}/…` — 계정 경로라 **새 계정 폴더로 복사 → 기록 경로 바꿈 → 옛 파일 삭제**.

**매출 · 숫자:**
- 계약(session_log)은 회원과 함께 옮긴다 → 회원의 남은 수업 · 재등록 흐름이 이어짐.
- 옮겨 온 계약은 `imported_from`(옛 계정) · `imported_at` 표시 → 새 계정의 **매출 · 등록률 · 급여 계산에서 '이동 전 기록'은 빼고**, 회원 화면 · 남은 수업에는 그대로 씀.
- 떠나는 쪽(센터)에는 **정산 · 세무용 사본**(그 회원 계약의 금액 · 날짜만 · 이름 가림)을 `moved_out_ledger`로 남긴다 → 센터 매출 추이 · 정산이 과거 숫자를 잃지 않음. **[결정]**

**겹침:** 받는 계정에 같은 전화번호 회원이 있으면 **하나로 합치기**(기록은 붙이고 회원 정보는 받는 쪽 우선) — 합칠지 따로 둘지 화면에서 고름.

**회원 동의:** 운영자(개인정보 처리자)가 바뀌는 일이라 **회원 동의를 받은 회원만** 옮긴다.
- 회원 페이지 첫 화면에 "앞으로 ○○(새 운영자)이 기록을 관리해요. 함께 옮길까요? [옮겨 주세요] [옮기지 않을래요]" · 14일 안 답 없으면 **옮기지 않음**(기본값 = 안전).
- 동의 기록 = `member_consent` kind `transfer`(누가 · 어디서 → 어디로 · 시각).
- 회원 페이지 **링크는 그대로**(토큰 유지) · 운영 이름만 바뀜.

## 4. 개인 → 센터 합류

1. **대표:** 트레이너 관리 › [트레이너 추가] 옆 **[개인 계정 트레이너 초대]** → 그 트레이너의 이메일 입력(이미 가입된 개인 계정 · 좌석 확인).
2. **트레이너:** 앱을 열면 "○○ 센터에서 초대했어요" 카드 → 옮길 회원 고르기(기본 전부) · 겹치는 회원 확인 → [합류하기].
3. 서버: 트레이너 로그인을 센터 계정 소속(role trainer)으로 바꾸고 → 이동 코어(동의한 회원부터 · 나머지는 동의가 오면 이어서) → 개인 계정은 **닫힘**(빈 계정 · 파기 예약).
4. **개인 구독:** 즉시 끝냄(빌링키 삭제 · 다음 결제 없음) → **남은 기간 = 포인트**(5장).
5. 합류 뒤: 급여 방식은 센터 대표 것 · 가격표는 본인 것 유지(대표 결정) · 일하는 방식 · 상호 칸은 사라짐(센터 이름을 씀).

## 5. 센터 → 개인 독립

**시작은 두 가지:**
- **대표가 허락:** 트레이너 관리 › 트레이너 줄 › [개인 계정으로 독립 허락] → 데려갈 수 있는 회원 범위(담당 회원 전부 / 고른 회원 / 없음).
- **센터 해지:** 해지 확인 창에서 "트레이너들이 개인으로 이어 쓸 수 있게 할까요?" → 체크하면 모든 트레이너에게 독립 허락(담당 회원 전부).

1. **트레이너:** "개인 계정으로 이어서 쓸 수 있어요" 카드 → 일하는 방식 · 상호 → 개인 요금제 카드 등록(**체험 7일** · 이미 체험했어도 이 경우는 줌 **[결정]**).
2. 서버: 새 개인 계정 생성(**로그인 그대로** · trainer.account_id 바꿈 · role owner) → 이동 코어(동의한 회원만).
3. 떠난 센터: 그 트레이너는 '퇴사' 표시 · 좌석 빔 · 센터에는 정산용 사본만.

**[결정]** 대표 허락 없이 트레이너가 스스로 독립(회원 없이 빈 계정만)하는 것도 둘지 — 추천: 둔다(로그인 유지가 목적 · 회원은 안 따라감).

## 6. 포인트 (남은 개인 구독 기간)

- 계산: 남은 일수 × (월 요금 ÷ 그달 일수) → 10원 단위 내림 · 체험 기간 중이면 0.
- 저장: `account_credit`(계정 · 금액 · 이유 · 만든 날 · 유효기간 1년) + 쓴 기록.
- 쓰기: 결제 작업이 청구 금액에서 먼저 뺌(0원이면 결제 없이 기간만 연장 · 영수증에 '포인트 사용').
- **합류할 때는 센터 결제에 넘겨 씀**(트레이너는 더 결제할 일이 없으므로) · 나중에 다시 독립하면 남은 포인트를 씀.
- **환불:** 기본은 포인트, **원하면 일할 환불**(문의 → 토스 부분 취소) — 전자상거래 · 소비자분쟁해결기준상 중도 해지 환급 요구에 대비. 약관에 명시.

- 약관 11조(처리위탁 · 해지 30일 파기 · 이전) — 읽기 전용 30일 · 내보내기 · 이전 절차 반영.
- 처리방침 — 이전 시 '처리자 변경'과 회원 동의 · 동의 안 하면 원래 운영자에 남고 30일 뒤 파기.
- 회원 이전 동의 문구 · 포인트 · 환불 조항.

## 8. 정해 주실 것 모음

1. 해지 뒤 **30일 읽기 전용 → 파기** 맞는지
2. 독립할 때 떠나는 센터에 **정산용 사본**(금액 · 날짜만) 남길지 — 추천: 남김
3. 회원 이전 동의 기한(추천 14일 · 답 없으면 안 옮김)
4. 독립하는 트레이너에게 **체험 7일**을 다시 줄지 — 추천: 줌
5. 대표 허락 없는 **회원 없는 독립**(로그인만 유지) 허용 — 추천: 허용
6. 포인트 유효기간(추천 1년) · 합류 시 센터 결제에 넘겨 쓰기
