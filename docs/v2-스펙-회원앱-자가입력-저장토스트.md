# v2 스펙 — 회원앱 자가입력 저장 토스트 (저위험 ②)

> **목적:** 회원앱 자가입력 3종(유산소·비포애프터 사진·개인운동)의 **저장/삭제 성공 시 토스트 피드백** 추가. 현재는 성공 시 폼만 비우고 조용히 `onReload` → 특히 `mode="form"`(목록 안 보임)에선 저장됐는지 확인이 안 됨. 공유 `Toast`/`useToast` 이식.
> **협업:** 웹Claude 스펙+리뷰, CC 구현, 대수 커밋. **additive · 로직/RLS/payload/저장경로 전부 불변** — 성공 분기에 `showToast(...)` 한 줄씩만 추가. 새 상태·prop 스레딩 없음.
> **파일:** `app/m/[token]/page.jsx` 1개 (mount-cache 아님 → 웹Claude 재스테이징 리뷰 가능). **1커밋.**
> **순수함수 0 · 마이그레이션 0 · fetch 0.**

---

## 배경 — 현재 구조 (3 섹션 동일 패턴)

`app/m/[token]/page.jsx` 안에 자가입력 컴포넌트 3개(모두 같은 골격):
- **CardioSection** (유산소 · `cardio_log` · Eyebrow "유산소 기록")
- **PhotoSection** (비포애프터 · `member_photo` · 압축→업로드→insert)
- **ScheduleSection** (개인운동 · `schedule_check` · Eyebrow "개인운동 기록")

각 컴포넌트의 `add`(저장)·`remove`(삭제) 핸들러는 하드닝(`.select()` 0행 실패 가드) 후 성공 시:
```js
// 성공 분기 (예: CardioSection.add)
setKind(""); setMinutes(""); setNote("");  // 폼 클리어(있는 것만)
await onReload();
setBusy(false);
```
→ **성공 알림이 없음.** 실패는 `err` state로 인라인 rose 텍스트 표시(유지).

공유 토스트(트레이너 앱이 이미 사용):
- `useToast(ms=3500)` → `{ toast, showToast }`. `showToast(msg)`가 메시지 세팅 후 3.5초 뒤 자동 클리어.
- `<Toast message={toast} />` → 화면 하단 중앙 · 체크 아이콘 · message 비면 렌더 안 함(fixed·DOM 부담 0).

## 변경 — 3 섹션에 토스트 추가 (동일 패턴 ×3)

### 1) import 추가 (파일 상단, 기존 `@/components/ui/*` import 옆)
```js
import Toast from "@/components/ui/Toast";
import { useToast } from "@/hooks/useToast";
```

### 2) 각 섹션 컴포넌트에 useToast + Toast 렌더 + showToast 호출

**방식:** 섹션마다 자체 `useToast()` 보유(prop 스레딩 없음 · 섹션 독립 · 동시에 하나만 활성이라 충돌 없음). 3섹션 각각:

**(a) 훅 선언** — 기존 `const [busy, setBusy] = useState(false); const [err, setErr] = useState("");` 옆에 추가:
```js
const { toast, showToast } = useToast();
```

**(b) 성공 분기에 showToast 한 줄** — `add`/`remove`의 `.select()` 실패 가드(`if (error || !data || data.length === 0) { … return; }`) **통과 직후**:

| 컴포넌트 | 핸들러 | 추가 위치 | 메시지 |
|---|---|---|---|
| CardioSection | `add` | `setKind("")…` 클리어 직전/직후 | `showToast("유산소 기록을 저장했어요");` |
| CardioSection | `remove` | `await onReload()` 직전 | `showToast("기록을 삭제했어요");` |
| PhotoSection | `add` | `await onReload()` 직전 | `showToast("사진을 저장했어요");` |
| PhotoSection | `remove` | 스토리지 remove 후 `await onReload()` 직전 | `showToast("사진을 삭제했어요");` |
| ScheduleSection | `add` | `setNote("")` 직전/직후 | `showToast("기록을 저장했어요");` |
| ScheduleSection | `remove` | `await onReload()` 직전 | `showToast("기록을 삭제했어요");` |

> 삭제 토스트는 저장과 짝이라 함께 넣음(저위험·일관성). 저장만 원하면 `remove`쪽 3줄은 빼도 됨.

**(c) Toast 렌더** — 각 섹션 return의 JSX 안 아무 데나(fixed라 위치 무관 · 보통 최상단 `<section>`/`<>` 바로 안 또는 끝):
```jsx
<Toast message={toast} />
```
- CardioSection: `<section className="mb-8">` 안 끝(`</section>` 직전).
- PhotoSection: 최상위가 `<>…</>` 프래그먼트 → 그 안 끝(`</>` 직전).
- ScheduleSection: `<section className="mb-8">` 안 끝.

## 불변·리스크

- **로직/RLS/payload/저장경로 불변.** `insert`/`delete`/`onReload`/`compressImage`/스토리지 업로드 전부 그대로. 성공 분기에 `showToast` 호출만 추가.
- **실패 경로 무변** — 기존 `err` 인라인 표시 유지(토스트는 성공 전용).
- **스레딩 없음** — 섹션마다 자체 `useToast`. 세 `<Toast/>`가 DOM에 있어도 message 없으면 null 렌더 → 동시에 최대 1개만 표시(한 번에 한 액션).
- **데모 모드(`!memberSupabase`)** — 기존처럼 `setErr` 후 early return이라 토스트 안 뜸(정상).
- **접근성/DS** — Toast는 기존 프리미티브 그대로(색·위치 검증됨). 새 색 클래스 0.
