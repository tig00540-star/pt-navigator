## 0. additive 판정 요약 (대수 요청 — "먼저 additive 가능한지부터")

| 요소 | 방법 | additive? |
|------|------|-----------|
| 이달 매출 | `revenueInMonth(contracts, ym)` (기존) | ✅ 재사용 |
| **이달 목표(게이지)** | `trainer_goal` **SELECT 1개 추가** → 계정 트레이너 목표 합산 | ✅ **단, 쿼리 1개 추가**(마이그레이션 X · 아래 ⚠️) |
| 다음달 예측(신규) | OT진행수 × `otFunnel` 전환율 × **`avgNewAmount`(신규 순수함수)** | ✅ 순수함수 1개 추가 |
| 다음달 예측(재등록) | `expiringMembers` × `reregisterStats` 재등록률 × `avgReregisterAmount` (전부 기존) | ✅ 재사용 |
| 신규/재등록 구성비 | **`revenueCompositionInMonth`(신규 순수함수)** = Σ `revenueByTrainer`와 동치 | ✅ 순수함수 1개 추가 |
| 환불 추이 | **`revenueTrendByMonth`(신규 순수함수)** — `refund_amount`·`refunded_at` 기존 컬럼 | ✅ 순수함수 1개 추가 |
| **미수금(受金 미납)** | — | ❌ **불가 — 스키마에 미납 컬럼 없음(§6)** |

**결론:** 앞 3기능(#1/#4/#2)은 "DB 쿼리 추가 0"이었으나, **#3의 목표 게이지만 예외적으로 `trainer_goal` SELECT 1개를 추가**해야 한다. 이유:
- 앞 3기능은 admin이 이미 로드한 6배열(`user_table`·`ot_log`·`session_log`·`daily_workout_log`·`pay_scheme`·`payroll_run`)만으로 완결됐다. 목표(`target_revenue`)는 그 어느 배열에도 없다 — 별도 `trainer_goal` 테이블(2026-07-12 이미 존재).
- ⚠️ **하지만 마이그레이션 0 · RLS 무변**이다: `trainer_goal`은 이미 있고, 정책 `trainer_goal_sel using (account_id = auth_account_id() and (auth_is_owner() or trainer_id = auth.uid()))`가 **원장에게 계정 전체 목표 SELECT를 이미 허용**한다. 즉 "새 쿼리 1개"일 뿐 스키마·정책은 안 건드린다.

## 2. `lib/memberStatus.js` — 신규 순수함수 4종 (파일 끝에 append · 전부 검증본)

> 전부 순수(기준시각 주입 · 모듈 내 `new Date()`/`Date.now()`/`Math.random()` 금지 · `kstYm` 재사용). `revenueByTrainer`·`revenueInMonth` 바로 아래 구간에 두면 응집도 좋음(위치는 CC 재량, append도 무방).

```js
/* =========================================================================
   #3 매출 파이프라인·예측 — 순수 파생 (admin fetch 배열 주입).
   전부 additive · DB/스키마 무변. 회원기반(forecast)은 hidden 제외된 visible을 받는다(호출부 책임).
   ========================================================================= */

/**
 * 신규 계약 평균금액 — avgReregisterAmount의 신규판(예상 신규매출 추정용).
 * counts_as_revenue & kind!=='reregister'(신규+이월null 포함) & amount_total 숫자 평균. 표본0=null.
 * ※ revenueByTrainer가 kind null을 newRev로 접는 것과 동일 규칙.
 * @returns {number|null}
 */
export function avgNewAmount(contractRows) {
  const rows = (Array.isArray(contractRows) ? contractRows : []).filter(
    (c) => c && c.counts_as_revenue && c.kind !== "reregister" && typeof c.amount_total === "number"
  );
  if (!rows.length) return null;
  return Math.round(rows.reduce((s, c) => s + c.amount_total, 0) / rows.length);
}

/**
 * 이달 매출 구성 — 신규/재등록 분해 + 환불 + 순매출(net). Σ revenueByTrainer와 동치.
 * 매출=started_at 해당월+counts_as_revenue · 환불=refunded_at 해당월. ym 주입.
 * @returns {{newRev,reRev,refund,gross,net,cntNew,cntRe,newShare,reShare}}
 */
export function revenueCompositionInMonth(contractRows, ym) {
  const rows = Array.isArray(contractRows) ? contractRows : [];
  let newRev = 0, reRev = 0, refund = 0, cntNew = 0, cntRe = 0;
  for (const r of rows) {
    if (!r) continue;
    if (r.counts_as_revenue && typeof r.started_at === "string" && kstYm(r.started_at) === ym) {
      const amt = r.amount_total ?? 0;
      if (r.kind === "reregister") { reRev += amt; cntRe += 1; }
      else { newRev += amt; cntNew += 1; }
    }
    if (r.refund_amount && typeof r.refunded_at === "string" && kstYm(r.refunded_at) === ym) refund += r.refund_amount;
  }
  const gross = newRev + reRev;
  return { newRev, reRev, refund, gross, net: gross - refund, cntNew, cntRe,
    newShare: gross ? newRev / gross : null, reShare: gross ? reRev / gross : null };
}

/**
 * 월별 매출/환불 추이 — ym(끝월) 기준 과거 months개월(과거→현재 순).
 * rev=계약월 매출 · refund=처리월 환불 · net=rev-refund. 순수: ym 문자열 정수연산(Date 안 씀).
 * @param {string} ym 'YYYY-MM' · @param {number} months 기본 6
 * @returns {Array<{ym,rev,refund,net}>}
 */
export function revenueTrendByMonth(contractRows, ym, months = 6) {
  if (typeof ym !== "string" || !/^\d{4}-\d{2}$/.test(ym)) return [];
  const y = Number(ym.slice(0, 4)), m = Number(ym.slice(5, 7)); // m: 1..12
  const list = [];
  for (let i = months - 1; i >= 0; i--) {
    let mm = m - 1 - i, yy = y;                 // 0-index 월에서 i개월 뒤로
    while (mm < 0) { mm += 12; yy -= 1; }
    list.push(`${yy}-${String(mm + 1).padStart(2, "0")}`);
  }
  const idx = new Map(list.map((k, i) => [k, i]));
  const rev = new Array(list.length).fill(0);
  const refund = new Array(list.length).fill(0);
  for (const r of Array.isArray(contractRows) ? contractRows : []) {
    if (!r) continue;
    if (r.counts_as_revenue && typeof r.started_at === "string") { const k = kstYm(r.started_at); if (idx.has(k)) rev[idx.get(k)] += (r.amount_total ?? 0); }
    if (r.refund_amount && typeof r.refunded_at === "string") { const k = kstYm(r.refunded_at); if (idx.has(k)) refund[idx.get(k)] += r.refund_amount; }
  }
  return list.map((mo, i) => ({ ym: mo, rev: rev[i], refund: refund[i], net: rev[i] - refund[i] }));
}

/**
 * 다음달 매출 예측(추정) — 두 파이프라인 합. 회원은 hidden 제외된 visible을 받는다(호출부 책임).
 *  신규   = 현재 OT 진행(viewFor 'ot') × 과거 전환율(otFunnel) × 신규 평균계약(avgNewAmount)
 *  재등록 = 만료임박(expiringMembers) × 재등록률(reregisterStats) × 재등록 평균계약(avgReregisterAmount)
 * 재료 하나라도 null(표본0)이면 해당 파이프라인 예측 null. 둘 다 null이면 total null(추정 불가).
 * @returns {{otPipeline,convRate,avgNew,expectedNew,expiringCount,reregRate,avgRe,expectedRe,total}}
 */
export function revenueForecastNextMonth(members, otRows, contracts, logs, { nowISO } = {}) {
  const mem = Array.isArray(members) ? members : [];
  const otPipeline = mem.filter((m) => m && viewFor(m) === "ot").length;
  const f = otFunnel(mem, otRows);
  const convRate = f.intake ? f.confirmed / f.intake : null;
  const avgNew = avgNewAmount(contracts);
  const expectedNew = (convRate != null && avgNew != null) ? Math.round(otPipeline * convRate * avgNew) : null;

  const exp = expiringMembers(mem, contracts, logs, { nowISO });
  const rr = reregisterStats(contracts);
  const reregRate = rr.rate;
  const avgRe = avgReregisterAmount(contracts);
  const expectedRe = (reregRate != null && avgRe != null) ? Math.round(exp.length * reregRate * avgRe) : null;

  const total = (expectedNew == null && expectedRe == null) ? null : (expectedNew ?? 0) + (expectedRe ?? 0);
  return { otPipeline, convRate, avgNew, expectedNew, expiringCount: exp.length, reregRate, avgRe, expectedRe, total };
}
```

**검증 로그(웹Claude 로컬 실행 · 토이 데이터):**
- `avgNewAmount` = 1,100,000 (신규 c1/c2/c5 평균 · 인계 c7 제외) ✅
- `revenueCompositionInMonth(7월)` = `{newRev:240만, reRev:80만, refund:30만, gross:320만, net:290만, newShare:0.75}` · **net===revenueInMonth(290만)** ✅ · **Σ revenueByTrainer 동치** ✅
- `revenueTrendByMonth(7월,6)` = 2~7월 6행 · 7월 net 290만 · 6월 net 100만 · **각 net===revenueInMonth(해당월)** ✅
- `revenueForecastNextMonth` = `{otPipeline:2, convRate:0.6, avgNew:110만, expectedNew:132만, expiringCount:1, reregRate:0.667, avgRe:100만, expectedRe:66.7만, total:198.7만}` ✅
- 빈 데이터 → `total:null`(추정 불가) · 잘못된 ym → `[]` ✅

> ⚠️ 미세 주의: `avgReregisterAmount`/`avgNewAmount`는 `amount_total:0`인 계약도 숫자라 평균 분모에 포함(기존 `avgReregisterAmount` 동작 그대로 · RetentionConsole도 사용 중). 실데이터에선 0원 계약행이 드물어 무해.

## 4. `components/admin/RevenuePipeline.jsx` (신규)

> 4블록: ① 이달 매출/목표 게이지 · ② 다음달 예측(추정) · ③ 신규/재등록 구성비 · ④ 매출/환불 추이. **자체 계산 최소 · 파생함수 호출·렌더**(RetentionConsole/ConversionFunnel 패턴). **색: 우수/긍정=cyan · 위험/환불=rose(danger) · 브랜드/게이지=primary(red). emerald 금지(DS 초록제거).** 숫자는 `won()`·`font-mono`. 예측은 "추정" 명시(허위 확신 금지).

### 4-1. 골격 (props·visible·파생)
```jsx
"use client";
/* =========================================================================
   #3 매출 파이프라인·예측 — admin '매출' 탭.
   이달 매출/목표 게이지 · 다음달 예측(추정) · 신규/재등록 구성비 · 매출/환불 추이.
   admin이 이미 로드한 배열 + goals(trainer_goal)를 props로 받아 파생·렌더만.
   ★hidden = 회원기반 함수(forecast)만 visible로 걸러 넘김. 매출/환불/구성비는 계약기반이라 원본 contracts.
   색: 긍정 cyan · 위험/환불 rose · 게이지 primary(red). emerald 금지. 예측은 '추정' 명시.
   ========================================================================= */
import { useMemo, useState } from "react";
import { Wallet, Target, TrendingUp, PieChart, LineChart } from "lucide-react";
import {
  revenueInMonth, revenueCompositionInMonth, revenueTrendByMonth, revenueForecastNextMonth,
} from "@/lib/memberStatus";
import { won } from "@/lib/format";
import Card from "@/components/ui/Card";

const pctText = (r) => (r == null ? "—" : Math.round(r * 100) + "%");

export default function RevenuePipeline({ members = [], contracts = [], logs = [], otRows = [], trainers = [], goals = [], ym }) {
  const [nowISO] = useState(() => new Date().toISOString()); // 마운트 1회 고정(렌더 순수)

  // ★hidden 제외 — 회원기반(forecast)만.
  const visible = useMemo(() => members.filter((m) => m && !m.hidden), [members]);

  // 계약기반(매출·구성·추이)은 원본 contracts.
  const net = useMemo(() => revenueInMonth(contracts, ym), [contracts, ym]);
  const comp = useMemo(() => revenueCompositionInMonth(contracts, ym), [contracts, ym]);
  const trend = useMemo(() => revenueTrendByMonth(contracts, ym, 6), [contracts, ym]);
  const forecast = useMemo(
    () => revenueForecastNextMonth(visible, otRows, contracts, logs, { nowISO }),
    [visible, otRows, contracts, logs, nowISO]
  );

  // 목표 = 이달 계정 트레이너 목표 합. 미설정(합 0)이면 null.
  const goalsThisYm = useMemo(() => goals.filter((g) => g && g.ym === ym && g.target_revenue != null), [goals, ym]);
  const target = useMemo(() => goalsThisYm.reduce((s, g) => s + (g.target_revenue || 0), 0) || null, [goalsThisYm]);
  const goalPct = target ? net / target : null;
  const trainerCount = trainers.length;

  // ... 4-2 ~ 4-5 렌더
}
```

## 6. 미수금(受金 미납) — 스코프 아웃 (**결정됨: 제외**)
> **대수 확정(2026-07-25): 1번(이번 스코프 제외).** 블록④ "미수금 준비 중" 안내만. 아래는 근거·후속 옵션 기록.

**현재 스키마로 미수금은 파생 불가.** `session_log`(2026-07-10 pt-package + 2026-07-11 refund + 2026-07-19 reg-columns) 컬럼: `amount_total`(=매출 인식액)·`price_per_session`·`sessions_total`·`service_sessions`·`counts_as_revenue`·`kind`·`started_at`·`refund_amount`·`refunded_at`·`reg_*`. **"청구액 vs 실수납액" 구분 컬럼이 없다** → 미납/미수 잔액을 계산할 소재가 없음(프록시도 없음 · 분납 여부도 미기록).

세 선택지 — 대수 결정:
1. **(스펙 기본) 미수금 이번 스코프 제외.** 블록④에 "미수금 추이 준비 중" 안내만. #3의 나머지 4요소는 전부 additive로 완성. **← 추천**(마이그레이션 0 유지 · 규율 일관).
2. **후속 마이그레이션으로 분리.** `session_log`에 `paid_amount integer`(또는 `unpaid_amount`) 컬럼 추가 → 미수금 = `amount_total − paid_amount`. **입력 UI(계약 폼에 수납액)·백필까지 딸려서 별도 스프린트**(additive 규율 밖 · #3와 분리). 스케치:
   ```sql
   -- 후속(결정 시): alter table session_log add column if not exists paid_amount integer;
   -- 미수금 = counts_as_revenue 계약 중 (amount_total - coalesce(paid_amount, amount_total))의 합. 기본=완납 가정.
   ```
3. **개념 재정의.** 대수가 말한 "미수금"이 미납이 아니라 "환불 예정/보류" 등 다른 뜻이면 알려주면 그에 맞춰 재설계.

**이번 배치는 1번(제외)으로 스펙됨.** 2/3을 원하면 별도 스펙으로 뺀다.
