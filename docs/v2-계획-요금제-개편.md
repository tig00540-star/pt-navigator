## 2. 설계 핵심

### 2-1. `account.plan`은 건드리지 않는다
`plan='premium'`은 **회원 전용 페이지 관문**(`auth_account_plan()` · `issue_member_token` · `auth_member_id` · `member-auth`)이다. 베이직도 회원 페이지를 쓰므로 유료 계정은 전부 `premium` 그대로 둔다.
요금 등급은 **`account.billing_plan`** 하나로: `basic` | `solo`(= 화면 이름 '프로') | `center`. 키 `solo`는 코드 곳곳(`PLANS` · `trainerSeats` · `planAmount` · 결제 작업)에서 쓰여 이름만 '프로'로 바꾼다.
- 개인 계정(`account.type='solo'`)은 `basic` · `solo` 중 고름 · 센터 계정은 `center`만. 서버가 `account.type`으로 검증(화면 값 믿지 않음 · 2026-10-06 원칙 유지).
- `lib/plans.js`에 `basic` 추가 · `amount` = 부가세 포함 실제 결제 금액 · `regular`(정가 취소선)는 유지할지 **[결정 D1]**.

### 2-2. AI 사용 기록 `ai_usage` (새 표)
`id · account_id · trainer_id · kind(voice | prep | inbody | roadmap | salesbook | owner | monthly | cues) · unit_key · counted(bool) · member_id · model · input_tokens · output_tokens · cache_read_tokens · cost_usd · ym(KST 'YYYY-MM') · created_at`
- **세는 단위 = `unit_key` 고유(계정 · ym 안에서):** 준비 = `prep:{member}:{ot r1|ot r2|contract id}` · 음성일지 = `voice:{요청 id}` · 인바디 = `inbody:{measurement id}` · 로드맵 = `roadmap:{member}`. 같은 키 다시 만들기 = 새로 세지 않음(행은 남겨 원가는 기록).
- 세일즈북 · 대표 보고서 · 월간 결산 · 장비 큐 = `counted=false`(원가 기록만).
- **이중 차감 방지:** AI 부르기 **전**에 `unique(account_id, ym, unit_key) where counted` 로 자리 잡기 → 실패하면 그 행 지움(실패는 안 셈) → 성공하면 토큰 · 원가 채움.
- 쓰기는 서버(service_role)만 · 읽기 = 대표 · 본인 계정(사용량 화면). 새 SELECT 규칙 → `select refresh_read_only_policies();` 다시 실행(해지 뒤 30일 읽기 규칙).
- 덤: 이 표가 **실제 원가 실측**이 된다(지금 원가는 저장 출력 기준 추정 · Opus 생각 토큰은 추정).

### 2-3. 한도 계산 `ai_quota(account)` (DB 함수 · 서버 · 화면 공용)
- 기본 한도: 베이직 = 5기능 각 3 · 프로 = voice 120 · prep 25 · inbody/roadmap 공정 사용 각 60 **[결정 D2]** · 센터 = voice 300 + 100×추가 좌석 · prep 60 + 20×추가 좌석 · inbody/roadmap 각 150.
- + 그달 산 팩(`ai_credit` 표 · 아래 4).
- 남은 수 = 한도 − 그달 `counted` 수. **달 = 달력 월(KST 1일 0시 리셋)** **[결정 D3 · 추천]**(결제일 기준보다 "이번 달 N번"이 이해 쉬움).
- 센터는 계정 전체 공용(트레이너별 나눔 없음).

### 2-4. 서버 잠금(화면만 숨기면 주소로 직접 부를 수 있음)
- `lib/requireTrainer` 다음에 `lib/aiQuota` `reserveAi(sb, { account, trainer, kind, unitKey })` → 남은 수 0이면 **402 `{ code: "quota", kind, left: 0, plan }`**.
- 적용: `ot-brief`(first · second · reregister = prep · inbody · roadmap · salesbook 3종은 그 회원 그달 준비가 있거나 프로 이상일 때만 · 아니면 402) · `voice-log`(STT 전에 예약 · STT/요약 실패면 반환) · `machine-cues`·`owner-report`·예약 작업 = 기록만.
- 체험(7일) = 프로 · 센터 한도 그대로.

## 3. 결제 · 요금제 바꾸기

- **결제벽(`AuthGate` Paywall):** 개인 계정 = [베이직 19,900] [프로 59,000(추천)] 카드 2장 · 센터 = 센터 1장. 카드 등록 → `billing/confirm`이 고른 등급을 `account.type`으로 검증 → `billing_plan` 저장.
- **결제 작업(`charge-subscriptions`):** 금액 = `planAmount(billing_plan)` + 센터 추가 좌석 × 39,900.
- **설정 › 구독 관리(`SubscriptionCard`):** 지금 요금제 · 이번 달 사용량(음성일지 n/120 · 준비 n/25 …) · [프로로 올리기] [베이직으로 내리기] · 추가 팩 · (센터) 트레이너 추가 수.
- **올리기(베이직 → 프로)** **[결정 D4]**
  - 추천: **바로 프로 + 남은 기간 차액 일할 결제**(빌링키 · 요금제 변경이라 정기결제 범위). 다음 결제일부터 59,000원.
  - 대안: 바로 프로 · 차액 없이 다음 결제일부터 59,000원(단순하지만 손해 소폭).
- **내리기(프로 → 베이직):** 다음 결제일부터(환불 없음 · 그때까지 프로).
- **센터 트레이너 추가** **[결정 D5]**: 추천 = 바로 좌석 열림 + 다음 결제일부터 청구(첫 달 일할 없음 · 단순). `account.extra_seats`(int · 서버 라우트로만 변경) · `create-trainer` 좌석 관문이 3 + extra_seats로.

## 4. 추가 팩

- **표:** `ai_credit`(account_id · kind voice | prep · amount · ym · payment_id · created_at) · 그달 말 소멸.
- **결제:** 토스 **일반결제(결제창 · 매번 카드 인증)**. 빌링키로 긁지 않는다 — 토스 문서: 자동결제는 "리스크 검토 및 추가 계약 후" · "정기 구독형 서비스가 아니라면 정책적으로 자동결제 사용이 제한". 팩은 정기 구독이 아니라 결제창으로.
  - 흐름: [10번 더 사기] → 결제창 → `/billing/pack/success?paymentKey&orderId&amount` → `/api/billing/pack`(service_role · 금액 서버 검증 · `/v1/payments/confirm` · `payment` 기록 · `ai_credit` 넣기).
- **보이는 곳:** 앱 안 — 남은 수가 적을 때(준비 3번 이하 · 음성일지 10건 이하) AI 버튼 자리 · 구독 관리. 랜딩 — 가격 카드 아래 한 줄 + 자주 묻는 질문(아래 6).
- **환불** **[결정 D6]** 추천: 산 뒤 7일 안 **하나도 안 썼으면 전액 환불** · 한 번이라도 썼으면 환불 없음 — 디지털 콘텐츠 청약철회 제한이라 **구매 전 화면에 미리 알림 필수**(전자상거래법 제17조 제2항 · 제6항). 법무 에이전트 점검.
- 베이직은 팩을 못 삼(프로로 올리기 안내) **[결정 D7 · 추천]**.

- **자주 묻는 질문(두 랜딩):**
  - "AI를 다 쓰면 어떻게 되나요?" → 기록 · 회원 관리는 그대로예요. AI만 그달 말까지 멈추고, 필요하면 추가 팩을 사서 바로 이어 쓸 수 있어요. 다음 달 1일에 다시 채워져요.
  - "'준비 1번'은 어떻게 세나요?" → 회원 1명의 OT 한 차수, 또는 재등록 한 번이 1번이에요. 세일즈북 · 다시 만들기는 세지 않아요.
  - "베이직에서 프로로 바꿀 수 있나요?" → 설정에서 언제든 바로 바꿀 수 있어요(D4 결정대로 문구).
