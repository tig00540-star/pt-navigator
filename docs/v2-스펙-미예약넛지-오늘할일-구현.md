# v2 구현 스펙 — 미예약 넛지 "다음 예약 미정" (오늘 할일 위젯)

> **확정:** 잔여 세션이 남은 활성 PT 회원인데 **앞으로 잡힌 예약이 없는** 회원을 트레이너 '오늘 할일'에서 잡아 다음 수업 예약을 넛지 → 리텐션(발길 끊김 예방). 만족의 결과로서 재등록이라는 제품 철학에 부합.
> **대전제:** 기존 '오늘 할일' 위젯 패턴 그대로(self-fetch · 순수 파생 · 빈배열이면 null). **새 테이블 0 · write 0 · RLS 무변 · 마이그레이션 0.** `appointment`/`session_log`/`daily_workout_log`는 이미 있는 테이블(기존 SELECT 정책).
> **범위:** ①`lib/memberStatus.js` 신규 순수함수 `unbookedActiveMembers`(기존 `viewFor`/`activeContract`/`remainingSessions` 재사용) ②신규 위젯 `components/views/NoNextBookingToday.jsx` ③`components/views/TodoTab.jsx` 배선 1줄. **`app/page.jsx` 무변**(TodoTab이 이미 `members·uid·onSelect` 전달).
> 흐름: 이 스펙 → CC(diff) → 대수(git diff) → 웹Claude(검토). 커밋 대수 직접.
> ⚠️ **mount-cache:** `lib/memberStatus.js`는 재스테이징이 옛 바이트 → **diff는 대수가 `git diff`로.** (TodoTab·신규 위젯은 정상 스테이징 OK.)

## 0. 정의 — 누가 넛지 대상인가

**대상 = 활성 PT(`viewFor==="pt"`) · 활성 계약 존재 · 잔여 세션 total>0 · '앞으로 잡힌 booked 예약' 없음.**

- **"앞으로 잡힌 예약"** = `appointment.status==="booked"` && `start_at > 지금`. **과거 booked(=미처리 예약)·canceled·done은 upcoming으로 안 침** → 그런 회원은 여전히 넛지 대상(다음 계획이 없으니까).
- 잔여 0 → 재등록 대상이지 예약 넛지 아님(제외). OT 회원 → 이번 범위 밖(제외 · 후속에서 '2차 OT 미예약' 확장 가능).
- **정렬:** 마지막 실수업 이후 경과일(gap) 내림차순 — 오래 안 온 회원 먼저(한 번도 안 왔으면 gap=null → 맨 뒤).

**⚠️ `PastDueAppointments`(미처리 예약)와 겹칠 수 있음:** 과거 booked만 있고 미래 예약 없는 회원은 두 위젯 모두에 뜬다 — **의도적**(액션이 다름: 지난 예약 완료/취소 처리 vs 다음 수업 새로 잡기). 위젯 순서는 미처리 예약 → 미예약 넛지로 배치.

## PART 1 — `lib/memberStatus.js` (신규 순수함수 · additive append)

> 기존 export·함수 불변. `pastDueAppointments`/`churnRiskByTrainer` 근처에 append. `viewFor`/`activeContract`/`remainingSessions`는 같은 파일 내 기존 함수(ChurnRiskToday에서 검증된 것) 재사용. ⚠️ mount-cache → `git diff` 리뷰.

```js
/**
 * 미예약 넛지 대상 — 잔여 있는 활성 PT인데 '앞으로 잡힌 booked 예약'이 없는 회원.
 * 리텐션: 다음 수업 계획이 비면 발길 끊김 → 먼저 예약을 잡게 넛지.
 * 순수. 기준시각(nowISO) 주입(모듈 내 now 금지). appointment는 호출부가 트레이너 스코프로 넘김.
 * ⚠️ upcoming = booked & start_at>now만. 과거 booked·canceled·done은 upcoming 아님(넛지 유지). 잔여0·OT 제외.
 * @param {Array} members   user_table 행(호출부가 담당 스코프로 넘김)
 * @param {Array} contracts session_log 행(계정 전체 · 회원별 filter)
 * @param {Array} logs      daily_workout_log 행(계정 전체 · 회원별 filter)
 * @param {Array} appts     appointment 행(트레이너 스코프 · booked 위주)
 * @param {{nowISO:string}} opts  nowISO 필수(잘못되면 [] 반환)
 * @returns {Array<{user_id, name, rem, gap, everCame}>} gap 내림차순(null 마지막).
 */
export function unbookedActiveMembers(members, contracts, logs, appts, { nowISO } = {}) {
  const now = Date.parse(nowISO || "");
  if (Number.isNaN(now)) return [];
  const cons = Array.isArray(contracts) ? contracts : [];
  const lg = Array.isArray(logs) ? logs : [];
  const upcoming = new Set();
  for (const a of Array.isArray(appts) ? appts : []) {
    if (!a || a.status !== "booked" || a.user_id == null) continue;
    const t = Date.parse(a.start_at || "");
    if (!Number.isNaN(t) && t > now) upcoming.add(a.user_id);
  }
  const out = [];
  for (const m of Array.isArray(members) ? members : []) {
    if (!m || viewFor(m) !== "pt") continue;
    if (upcoming.has(m.id)) continue;
    const mc = cons.filter((c) => c.user_id === m.id);
    const ml = lg.filter((l) => l.user_id === m.id);
    const active = activeContract(mc, ml);
    if (!active) continue;
    const rem = remainingSessions(active, ml);
    if (rem.total <= 0) continue;
    const done = ml.filter((l) => !l.voided && l.source !== "noshow");
    const last = done.map((l) => l.session_at ?? l.created_at).filter(Boolean).sort().slice(-1)[0] ?? null;
    const gap = last ? Math.floor((now - Date.parse(last)) / 86400000) : null;
    out.push({ user_id: m.id, name: m.name, rem: rem.total, gap, everCame: Boolean(last) });
  }
  return out.sort((a, b) => (b.gap ?? -1) - (a.gap ?? -1));
}
```
> **검증완료(Node · viewFor/activeContract/remainingSessions는 스텁, novel 로직 검증):** 미래 booked만 upcoming(과거 booked·canceled 제외→넛지 유지)·잔여0/OT 제외·gap 내림차순(null 마지막)·빈입력/nowISO 없음 → `[]`.

## PART 2 — `components/views/NoNextBookingToday.jsx` (신규 파일 · `git add` 먼저)

`PastDueAppointments` 패턴 그대로(self-fetch + 순수 파생 + DS 프리미티브 + 빈배열 null). props: `members`(scoped) · `uid` · `onSelect`.

```jsx
"use client";
/* =========================================================================
   오늘 할일 — "다음 예약 미정": 잔여 있는 활성 PT인데 앞으로 잡힌 예약이 없는 회원.
   판정=lib/memberStatus의 unbookedActiveMembers. 선택 시 스케줄로(onSelect id,9) 예약 잡기.
   self-fetch: session_log·daily_workout_log(계정) + appointment(booked·미래·트레이너 스코프). 빈배열 null.
   ⚠️ write 0 · 새 저장 0 — 순수 파생.
   ========================================================================= */
import { useEffect, useState } from "react";
import { CalendarPlus } from "lucide-react";
import { supabase } from "@/lib/supabaseClient";
import { unbookedActiveMembers } from "@/lib/memberStatus";
import ToneCard from "@/components/ui/ToneCard";
import SectionHeader from "@/components/ui/SectionHeader";
import ListRow from "@/components/ui/ListRow";

export default function NoNextBookingToday({ members, uid, onSelect }) {
  const [rows, setRows] = useState([]);

  useEffect(() => {
    if (!supabase) return;               // 데모: 집계 데이터 없음 → 빈 채로 숨김
    const nowISO = new Date().toISOString();
    let cancelled = false;
    (async () => {
      try {
        // appointment은 트레이너 스코프(uid)로 미래 booked만. contracts/logs는 계정 전체(회원별 filter는 순수함수가).
        const [ap, cs, ls] = await Promise.all([
          uid
            ? supabase.from("appointment").select("user_id, start_at, status, trainer_id")
                .eq("status", "booked").eq("trainer_id", uid).gte("start_at", nowISO)
            : Promise.resolve({ data: [] }),
          supabase.from("session_log").select("id, user_id, started_at, created_at, sessions_total, service_sessions, handed_over"),
          supabase.from("daily_workout_log").select("user_id, contract_id, session_at, created_at, voided, source"),
        ]);
        if (cancelled) return;
        setRows(unbookedActiveMembers(members || [], cs.data || [], ls.data || [], ap.data || [], { nowISO }));
      } catch {
        // 조회 실패 — 빈 채로 숨김 degrade.
      }
    })();
    return () => { cancelled = true; };
    // members 신원 바뀔 때 재계산(page.jsx가 loadMembers 후 새 배열).
  }, [uid, members]);

  if (!rows.length) return null;

  return (
    <ToneCard tone="neutral">
      <SectionHeader
        tone="neutral"
        icon={CalendarPlus}
        title="다음 예약 미정"
        count={rows.length}
        hint="잔여 있는데 다음 수업이 안 잡힘 — 먼저 예약을 잡으세요"
      />
      <div className="grid gap-2">
        {rows.map((r) => (
          <ListRow key={r.user_id} tone="neutral" name={r.name || "회원"} onClick={() => onSelect(r.user_id)}>
            <div className="mt-0.5 flex flex-wrap items-center gap-x-2 text-[11px] text-sub">
              <span className="font-medium">잔여 {r.rem}회</span>
              {r.gap != null ? (
                <span className={r.gap >= 14 ? "font-medium text-amber-600" : "text-muted"}>마지막 수업 {r.gap}일 전</span>
              ) : (
                <span className="text-muted">아직 첫 수업 전</span>
              )}
            </div>
          </ListRow>
        ))}
      </div>
    </ToneCard>
  );
}
```
> ⚠️ **DS 프리미티브 시그니처 확인:** `ToneCard`/`SectionHeader`/`ListRow`는 `PastDueAppointments`가 쓰는 것과 동일하게 사용 — CC가 그 파일의 실제 props(특히 `ListRow`의 `name`·`onClick`·children, `SectionHeader`의 `icon`/`title`/`count`/`hint`/`tone`)를 대조해 맞출 것. 어긋나면 PastDueAppointments 사용례를 정본으로.
> `tone="neutral"` — 미처리 예약과 같은 차분한 톤(ChurnRisk의 rose는 더 급한 이탈경보용). 대수가 원하면 `reapproach`(amber)로 조정 가능.

## 검증 체크리스트
1. **lint green** · 새 파일 `git add` 먼저 · 미사용 import 0.
2. **대상 정확** — 잔여 있는 활성 PT 중 미래 booked 예약 없는 회원만. 미래 예약 잡힌 회원은 사라짐. 잔여0·OT 제외.
3. **과거 booked·canceled는 넛지 유지** — 지난 예약만 있는 회원도 뜸(미처리 예약과 공존 · 의도).
4. **정렬** — 오래 안 온 회원 먼저(gap 내림차순 · 첫 수업 전=맨 뒤).
5. **동선** — 카드 탭 → '오늘' 탭 스케줄 보드로 스크롤, 그 회원 선택된 상태로 예약 잡기 가능(PastDueAppointments와 동일).
6. **빈/데모** — 대상 0이면 위젯 통째 null · `!supabase`(데모)면 null.
7. **RLS·write 없음** — 조회만. appointment 트레이너 스코프.
8. **handed_over** — 인계된 계약은 `activeContract`/`remainingSessions`가 이미 잔여0 취급 → 넛지 안 뜸(정상). 재배정 회원은 trainer_id 바뀌어 scoped에서 빠짐.
