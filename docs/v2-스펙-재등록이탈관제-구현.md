## 1. 지표 정의
`ym`·`nowISO` 기존과 동일. 판정 원천은 `lib/memberStatus.js`(단일 소재지).

| 지표 | 정의 | 원천 |
|------|------|------|
| 만료 임박 회원 | activeContract 존재 & `reregisterDue`(유료 잔여<10) PT 회원 | `expiringMembers`(신규) |
| 예상 재등록 매출 | 만료임박 수 × 과거 재등록 평균 계약금액 | `avgReregisterAmount`(신규) × count |
| 이탈위험 회원 | PT · 활성계약 · 잔여>0 · 14일+ 무수업 | `churnRiskMembers`(신규) |
| 방치 잔여세션 | 이탈위험 회원들의 잔여세션 합(=방치되는 세션) | 파생(컴포넌트) |
| 트레이너별 재등록률 | `session_log.reg_result` success/시도, 트레이너별 | `reregisterStatsByTrainer`(#1, 이미 있음) |

- **임계값**(조정 가능): 만료임박 유료잔여 `< 10`(기존 `reregisterDue` 기본), 이탈 `14일`(기존 `STALE_DAYS`).
- **예상 재등록 매출은 "추정"**임을 화면에 명시(과장·허위긴급성 금지 — 제품정의 §4). 과거 재등록 표본 없으면(`avgReregisterAmount==null`) 금액 숨기고 "표본 부족"으로.
- ⚠️ **hidden(환불·소프트삭제) 회원 제외** — admin은 `user_table.select("*")`로 hidden까지 로드하므로, **컴포넌트가 `members.filter(m=>!m.hidden)`로 걸러서** 관제 함수에 넘긴다(§3). 안 그러면 환불 회원이 이탈·만료임박에 잡혀 트레이너 화면과 불일치(#1에서 실제 재현·확정된 이슈).

## 2. 신규 순수함수 — `lib/memberStatus.js` (additive, 파일 끝 append)

> ⚠️ 이 함수들은 **받은 members 그대로** 처리한다(hidden 필터는 호출부=컴포넌트 책임 · §3). #1의 `churnRiskByTrainer`와 판정 로직 동일 — 후속 정리 배치에서 단일화 가능하나 이번엔 독립 유지.

```js
/* =========================================================================
   #4 재등록·이탈 관제 — 계정 전체 리스트 파생(원장 콘솔용). 전부 순수·기준시각 주입.
   hidden 필터는 호출부 책임(admin이 user_table 전체 로드 · 컴포넌트가 visible만 전달).
   ========================================================================= */

/**
 * 이탈위험 회원 목록 — ChurnRiskToday와 동일 판정을 계정 배열에서.
 * PT · activeContract 존재 · remainingSessions.total>0 · 마지막 실수업 gap ≥ staleDays.
 * @returns {Array<{user_id, trainer_id, gap, rem, everCame}>} gap 내림차순.
 */
export function churnRiskMembers(members, contracts, logs, { nowISO, staleDays = 14 } = {}) {
  const nowT = Date.parse(nowISO);
  const daysSince = (iso) => { if (!iso) return null; const t = Date.parse(iso); return Number.isNaN(t) ? null : Math.floor((nowT - t) / 86400000); };
  const cBy = new Map(), lBy = new Map();
  for (const c of Array.isArray(contracts) ? contracts : []) { if (c?.user_id == null) continue; if (!cBy.has(c.user_id)) cBy.set(c.user_id, []); cBy.get(c.user_id).push(c); }
  for (const l of Array.isArray(logs) ? logs : []) { if (l?.user_id == null) continue; if (!lBy.has(l.user_id)) lBy.set(l.user_id, []); lBy.get(l.user_id).push(l); }
  const out = [];
  for (const m of Array.isArray(members) ? members : []) {
    if (!m || viewFor(m) !== "pt") continue;
    const mc = cBy.get(m.id) || [], ml = lBy.get(m.id) || [];
    const active = activeContract(mc, ml);
    if (!active) continue;
    const rem = remainingSessions(active, ml);
    if (rem.total <= 0) continue;
    const done = ml.filter((l) => !l.voided && l.source !== "noshow");
    const last = done.map((l) => l.session_at ?? l.created_at).filter(Boolean).sort().slice(-1)[0] ?? null;
    const ref = last ?? active.started_at ?? active.created_at ?? null;
    const gap = ref ? daysSince(ref) : null;
    if (gap == null || gap < staleDays) continue;
    out.push({ user_id: m.id, trainer_id: m.trainer_id ?? "unknown", gap, rem, everCame: Boolean(last) });
  }
  return out.sort((a, b) => b.gap - a.gap);
}

/**
 * 만료 임박 회원 목록 — activeContract가 재등록 임계 도달(reregisterDue) PT 회원.
 * @returns {Array<{user_id, trainer_id, rem, active, gap}>} 유료 잔여 오름차순(급한 것 먼저).
 */
export function expiringMembers(members, contracts, logs, { basis = "paid", threshold = 10, nowISO } = {}) {
  const nowT = nowISO ? Date.parse(nowISO) : null;
  const daysSince = (iso) => { if (!iso || nowT == null) return null; const t = Date.parse(iso); return Number.isNaN(t) ? null : Math.floor((nowT - t) / 86400000); };
  const cBy = new Map(), lBy = new Map();
  for (const c of Array.isArray(contracts) ? contracts : []) { if (c?.user_id == null) continue; if (!cBy.has(c.user_id)) cBy.set(c.user_id, []); cBy.get(c.user_id).push(c); }
  for (const l of Array.isArray(logs) ? logs : []) { if (l?.user_id == null) continue; if (!lBy.has(l.user_id)) lBy.set(l.user_id, []); lBy.get(l.user_id).push(l); }
  const out = [];
  for (const m of Array.isArray(members) ? members : []) {
    if (!m || viewFor(m) !== "pt") continue;
    const mc = cBy.get(m.id) || [], ml = lBy.get(m.id) || [];
    const active = activeContract(mc, ml);
    if (!active) continue;
    if (!reregisterDue(active, ml, { basis, threshold })) continue;
    const rem = remainingSessions(active, ml);
    const done = ml.filter((l) => !l.voided && l.source !== "noshow");
    const last = done.map((l) => l.session_at ?? l.created_at).filter(Boolean).sort().slice(-1)[0] ?? null;
    out.push({ user_id: m.id, trainer_id: m.trainer_id ?? "unknown", rem, active, gap: last ? daysSince(last) : null });
  }
  return out.sort((a, b) => (a.rem[basis] ?? 0) - (b.rem[basis] ?? 0));
}

/**
 * 과거 재등록 평균 계약금액 — counts_as_revenue & kind='reregister' & amount_total!=null 평균.
 * 예상 재등록 매출 추정용. 표본 0이면 null(화면에서 금액 숨김).
 * @returns {number|null}
 */
export function avgReregisterAmount(contractRows) {
  const rows = (Array.isArray(contractRows) ? contractRows : []).filter(
    (c) => c && c.counts_as_revenue && c.kind === "reregister" && typeof c.amount_total === "number"
  );
  if (!rows.length) return null;
  return Math.round(rows.reduce((s, c) => s + c.amount_total, 0) / rows.length);
}
```

> `churnRiskMembers`의 버킷 빌드 패턴은 #1 `churnRiskByTrainer`와 동일(검증 완료본) — has/set/push로 통일.

## 3. 신규 컴포넌트 — `components/admin/RetentionConsole.jsx`
Props: `{ members, contracts, logs, trainers, ym }`. 자체 fetch 없음. `nowISO`는 마운트 1회 고정(`useState(()=>new Date().toISOString())`).

### 내부 계산(useMemo)
- **★hidden 필터(맨 위):** `const visible = useMemo(() => members.filter((m) => m && !m.hidden), [members]);` — 아래 관제 함수엔 **전부 `visible`을 넘긴다**(#1과 동일 규율 · 트레이너 화면 `ChurnRiskToday`/`RegisterDueToday`와 숫자 일치).
- `nameOf(trainer_id)` = `personName(trainers.find(t=>t.id===id)?.name)` (없으면 "미배정"/id앞 8자 — #1 `TrainerScorecard`와 동일 규약). 회원명은 `visible`에서 id→name 맵.
- `churn = churnRiskMembers(visible, contracts, logs, {nowISO})`
- `expiring = expiringMembers(visible, contracts, logs, {nowISO})`
- `avgRe = avgReregisterAmount(contracts)` (계약 기준 — hidden 무관)
- `expectedReRev = avgRe != null ? expiring.length * avgRe : null`
- `idleSessions = churn.reduce((s,c)=>s+c.rem.total, 0)`
- `reregByTrainer = reregisterStatsByTrainer(contracts)`(#1, 이미 있음) → 트레이너명 매핑

### 렌더 (섹션 4개 · DS `Card`/`ToneCard` 사용 · 인라인 카드 금지)
1. **상단 요약 타일 4개**: 만료임박 `{expiring.length}명` · 예상 재등록매출 `{expectedReRev!=null? won : "표본 부족"}` · 이탈위험 `{churn.length}명`(rose 톤) · 방치 잔여세션 `{idleSessions}회`. → 예상매출 타일에 "추정(과거 재등록 평균 {won(avgRe)} 기준)" 캡션. avgRe null이면 "재등록 이력 쌓이면 표시".
2. **만료 임박 리스트**(`ToneCard tone="renewal"`): 회원명 · 담당 트레이너 · 잔여(유료 {paid}·서비스 {service}) · 마지막수업 {gap}일 전 · 예상금액(avgRe). 정렬 유료잔여 asc. 빈 배열이면 "임박 회원 없음".
3. **이탈 위험 리스트**(`ToneCard tone="danger"`): 회원명 · 담당 · `{gap}일째 무수업`(everCame=false면 "등록 후 {gap}일 미방문") · 잔여 {total}회. 정렬 gap desc.
4. **트레이너별 재등록률 비교**: 트레이너명 + 재등록률 bar(성공/시도) — #1 리더보드 재등록 열과 값 일치. 표본 0 트레이너 "—".

### 색·톤 (★#1과 통일)
- 긍정/좋음 = **`text-cyan-700`**, 위험/주의 = **`text-danger-text`**(rose) — DS 초록제거 정책 준수(#1 `TrainerScorecard`와 동일).
- 이탈 카드 = `tone="danger"`(rose), 만료 카드 = `tone="renewal"`(sky/pt), 재등록률 bar = pt/cyan 계열. 전부 정적 리터럴 클래스(purge 안전 · 동적 조립 금지).
- 모바일 1열. 리스트 길면 상위 20 + "외 N명" 접기.
- ⚠️ **허위 긴급성 금지**: "예상 재등록 매출"은 **추정** 명시, D-day 카운트다운·긴급 문구 금지(제품정의 §4).
