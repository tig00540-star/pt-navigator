# PRD — 오직 트레이너 공식 홈페이지(랜딩) + 구독 결제

> 문서 성격: 신규 마케팅 홈페이지(랜딩페이지) 및 구독 결제 도입의 제품 요구사항 정의서(PRD).
> 관련 문서: 앱 정본은 `docs/MASTERPLAN.md`·`docs/PRD.md`. 이 문서는 **앱 외부에 공개되는 홈페이지**만 다룬다.
> ⚠️ 현재 폴더의 기존 홈페이지/마케팅 문서(`marketing/`, `docs/pt-navigator-*.md` 등)는 **참조하지 않는다**(사장님 지시).
> 상태: 초안(v0.1) · 결정 완료 항목은 §14 참고.

---

## 1. 배경 & 목적

- 앱(`오직 트레이너`)은 **로그인한 트레이너가 매일 쓰는 도구**다. 반면 홈페이지는 **아직 결제하지 않은 예비 트레이너를 설득해 구독까지 끌고 가는** 완전히 다른 목적·다른 관객을 위한 채널이다.
- 지금은 로그아웃 방문자가 `/`에 오면 **로그인 폼만** 본다 → 제품이 무엇인지, 왜 돈을 내야 하는지 설득하는 장치가 전무하다.
- 광고·인스타 바이오·공유 링크의 **도착지(랜딩)**가 필요하다: 길게 스크롤하며 설득하는 스토리텔링 + 결제 진입점.

**목적:** 예비 트레이너가 홈페이지 한 장을 훑고 → 제품 가치를 이해하고 → 무료 체험/구독으로 전환하게 만든다.

## 2. 목표 & 성공지표(KPI)

| 목표 | 지표 |
|---|---|
| 방문 → 앱 진입 전환 | 히어로/헤더 CTA 클릭률, `/signup` 도달률 |
| 가치 전달 | 스크롤 깊이(핵심기능·요금제 도달 비율) |
| 결제 준비 | (이후) 요금제 CTA → 결제 시작률, 구독 완료율 |
| 공유 확산 | OG 미리보기 정상 노출(카톡/인스타 공유 시) |

> 애널리틱스 도구(GA4/Amplitude 등)는 이후 결정. 이번 범위엔 계측 태그 자리만 확보.

## 3. 대상 사용자(페르소나)

- **1차:** 개인 트레이너 / 센터 소속 트레이너(20~40대). OT 세일즈·재등록·회원관리·급여정산에 스트레스가 있는 현장 종사자. 주 사용 기기 = **모바일(iPhone/Android)**.
- **2차:** 센터 원장·운영자(팀 단위 도입 결정권자).
- 함의: **모바일 우선(Mobile-first)** 설계 필수. 카피는 트레이너 현장 언어로.

## 4. 범위(Scope)

### 4.1 이번 스프린트 (In scope)
- 공개 랜딩페이지 1장(`/lp`), 아래 §6 섹션 전체.
- 반응형(모바일 우선) · 접근성 기본선 · OG/SEO 메타.
- 요금제 섹션(2~3단계 티어) UI.
- **결제는 "자리만"** — 요금제 CTA에서 결제/체험 진입점까지. 실제 PG(토스) 청구 배선은 이후(§7).

### 4.2 이후 단계 (Later)
- 토스페이먼츠 실연동(빌링키 발급 → 매월 자동청구 → `my_account_status()`에 구독상태 반영).
- 애널리틱스 계측, A/B 카피, 블로그/고객사례, FAQ 확장, 다국어.

### 4.3 범위 외 (Out of scope)
- 앱 본체(`app/page.jsx`)·회원앱(`/m`)·관리자(`/admin`) 변경.
- PWA `start_url`(`/`) 구조 변경 — **건드리지 않는다**(아래 §5).
- PG 가맹점 가입·API 키 발급·실결제 테스트 → **사장님 몫**(금융 자격증명은 대리 입력 불가).

## 5. 정보구조 & 라우팅

- **경로:** `/lp` (별도 공개 경로). 광고·공유 링크의 도착지. (추후 커스텀 도메인 루트를 여기에 연결 가능.)
- **게이트 우회:** `AuthGate`에서 `/m`(회원앱)과 동일하게 **완전 우회** 처리 → 로그인/구독 여부와 무관하게 누구나 즉시 열람(세션 조회 대기 없이 빠른 페인트). *(구현 완료: `components/AuthGate.jsx`에 `isLandingRoute` 분기 추가)*
- **앱·PWA 영향 0:** `/`(앱 본체)와 `start_url`은 그대로. 거대한 `app/page.jsx`를 리팩터하지 않는다.
- **CTA 목적지:**
  - "앱 시작하기 / 앱 열기" → `/` (로그아웃 시 로그인 폼, 로그인 시 앱).
  - "무료로 시작" → `/signup`.
  - 네비 앵커 → `#philosophy` · `#features` · `#reviews` · `#pricing`.

## 6. 페이지 구성(섹션별 요구사항)

순서대로 세로 스크롤. 각 섹션은 mono 아이브로 + 대형 한글 헤딩 시스템을 공유.

### 6.1 헤더(sticky)
- 워드마크(`오직`=먹색 / `트레이너`=레드) + 네비 앵커(데스크톱) + 우측 **"앱 열기"** CTA.
- 모바일: 워드마크 + CTA만(햄버거 없이 간결, 페이지가 스크롤로 흐름).
- 배경 반투명 + blur, 하단 라인. JS 없이 CSS sticky.

### 6.2 히어로 + 메인 CTA (요구사항: "앱을 열기 위한 CTA")
- **헤드라인(thesis):** 사장님 카피 정본의 핵심 — 예: "잘 모르겠으면, 따라만 하세요." (초heavy 대형 타입).
- 서브: "회원 맞춤 OT 준비부터 세일즈·클로징, 세일즈북 PPT까지 — 앱이 알려주는 대로 말하고, 운동하고, 보여주세요."
- CTA 2개: **[앱 시작하기]**(→`/`) + **[기능 둘러보기]**(→`#features`).
- **제품 비주얼:** 앱의 'OT 사전무장 컨닝페이퍼' 폰 목업(실제 디자인 언어 재현) — 무엇을 파는지 한눈에.

### 6.3 앱 소개 & 핵심 철학 (요구사항: "앱 소개 및 핵심 철학")
- 한 문단 소개 + 철학 한 줄. 톤: **다크 섹션 1개**로 대비 포인트.
- 메시지: "OT 입장 직전 3분, 앱 켜서 훑고 → 당당히 리드." "앱이 알려주는 대로 말하고·운동하고·세일즈하고·보여주세요."
- (앱 내부 철학 참고: '상향평준화', AI는 정답 제공이 아니라 **스파링 파트너** — 단, 랜딩 카피는 예비고객 설득 우선의 단순·강력한 버전을 사용.)

### 6.4 핵심 기능 8 (요구사항: "핵심기능")
- 사장님이 주신 **8개 기능 카피가 정본**(원문 §13 부록 보존).
- 표현: 트레이너의 "무기 8"로 편집. 각 항목 = 마커(01~08) + 짧은 제목 + 후크 문장 + 아이콘(lucide).
- 아이콘 매핑(앱에서 사용 확인된 것만): Compass · RefreshCw · NotebookPen · Users · Wallet · Brain · TrendingUp · Trophy.

| # | 제목(요약) | 한 줄 후크 | 대응 앱 기능 |
|---|---|---|---|
| 01 | 따라만 하세요 | OT 준비→세일즈→클로징→세일즈북 PPT 원스톱 | FirstOT/SecondOT AI |
| 02 | 재등록은 설계하는 것 | 운동일지·인바디·빈도 근거로 재등록 세일즈북 | 재등록 세일즈북 |
| 03 | 타이핑 대신 말로 | 수업 끝 5분 복기만 → 자동 정리·저장·회원 전송 | 음성일지(voice-log) |
| 04 | 회원이 셀프로 관리 | 유산소·식단·인바디·비포애프터 자가기록, 트레이너는 댓글만 | 회원앱 자가입력 |
| 05 | 급여 정산 자동 | 수업료 계산은 앱이, 확정만 | 급여/실적 |
| 06 | 링크만 저장하면 AI가 학습 | 성공·실패 클로징 모두 자산, 실전에 녹임 | AI 학습 |
| 07 | 쓸수록 똑똑해지는 앱 | 성공 클로징 학습·업데이트, 실패는 스스로 삭제 | 집단 학습 |
| 08 | 이벤트로 동기부여 | 트레이너가 여는 이벤트·경쟁으로 회원 재미·목표 | 오운완/이벤트 |

### 6.5 후기 (요구사항: "후기")
- 트레이너 후기 3~4개(카드형). **현재는 플레이스홀더 카피**(가상 페르소나: 연차·지역).
- ⚠️ **출시 전 실제 후기로 교체 필수.** 가공 후기를 '진짜'처럼 게시하지 않는다 — 개발 단계 플레이스홀더로 명시(`예시` 뱃지).

### 6.6 요금제 (결정: 2~3단계 티어)
- 3티어 예시: **라이트 / 프로(추천) / 팀·센터**. 가격은 **예시(출시 예정)** 명시.
- 각 카드: 이름 · 대상 · 가격 · 포함 기능 리스트 · CTA.
- 이번 범위 CTA = **"무료로 시작"(→`/signup`)** + "결제 연동 준비 중" 안내. 결제 버튼 자리(§7 seam) 마련.

### 6.7 최종 CTA
- "지금 시작하세요" 대형 배너 → `/`(앱 시작).

### 6.8 푸터
- 워드마크 · 슬로건(ONLY FOR TRAINER) · 섹션 링크 · 사업자정보/문의(플레이스홀더).

## 7. 결제(구독) — 토스페이먼츠

- **PG: 토스페이먼츠**(국내 정기결제 표준, 빌링키 자동결제). 이번 스프린트 = **자리만**.
- **이번 범위:** 요금제 카드에 결제/체험 진입점 + 코드 seam(주석 TODO). 실청구 없음.
- **이후 배선(설계 방향):**
  1. 티어 선택 → 토스 **빌링키 발급**(카드 등록) 위젯.
  2. 서버 라우트(예: `app/api/billing/*`, Node 런타임, service_role)에서 빌링키 저장 + 최초 청구.
  3. 매월 자동청구(스케줄) → 결과를 **구독상태로 반영** → 기존 `my_account_status()` / Paywall 게이트가 그대로 소비.
  4. 웹훅으로 결제 실패/취소 처리.
- **경계(중요):** PG 가맹 가입·시크릿키 발급·실결제 테스트는 **사장님이 수행**. 코드는 "키 넣으면 도는 상태"까지 제공. 자격증명은 `.env`(서버 전용), 클라 노출 금지.
- **연계:** 결제 성공 = 구독 활성 → 앱 진입 시 Paywall 해제. Paywall 문구의 "결제 연동은 준비 중입니다"를 실연동 시 교체.

## 8. 디자인 방향

- **차별화 원칙:** 앱 CRUD 화면과 결을 다르게, AI 기본형(크림+세리프 / 흑배경+형광 / 신문 조판) 회피.
- **타입이 주인공:** Pretendard Variable 초heavy(≈900) 대형 한글 헤드라인, 타이트 자간. 명령형 트레이너 화법("따라만 하세요", "보여주세요"). 데이터·라벨은 mono(Geist Mono).
- **시그니처 = 바늘(針):** 브랜드 마크의 단일 침("오직/ONLY, 한 방향" · 내비게이터)을 아이브로·섹션 마커의 관통 모티프로.
- **톤:** 라이트 베이스(앱과 일관) + **다크 '철학' 섹션 1개**로 대비. 절제된 모션 1~2곳(히어로 로드, 스크롤 리빌).
- **토큰 재사용:** `app/globals.css`의 브랜드 토큰(레드 `#dc2626`, ink `#13151b`, Pretendard). 색 클래스는 **정적 리터럴만**(purge-safe · CLAUDE.md UI 규약). 손수 카드/모달 대신 필요 시 `components/ui/*` 프리미티브.

## 9. 기술 구현

- **프레임워크:** Next.js 16 App Router, React 19, JS/JSX. 신규 파일 `app/lp/page.jsx`.
- **렌더링:** **서버 컴포넌트** 우선(콘텐츠가 초기 HTML에 → SEO·공유 유리). `export const metadata`로 OG/타이틀/설명.
- **인터랙션:** sticky 헤더·모바일 네비·리빌 모두 **가능한 한 JS 없이**. 스크롤 리빌은 순수 CSS `animation-timeline: view()`를 **점진적 향상**으로(미지원 Safari에선 콘텐츠 그대로 노출 · 콘텐츠 숨김 위험 0). `prefers-reduced-motion` 존중.
- **성능:** 헬스장 회선 고려 — 무거운 라이브러리 금지(framer-motion 등 미사용, 앱 정책 동일). 이미지 최적화(`next/image`).
- **접근성 기본선:** 키보드 포커스 가시, 명도대비 AA, 시맨틱 마크업, 리듀스드모션.
