# 스펙 — 오늘 할일: 미확인 수업 확인 요청 (오늘 스케줄 회원)

> **협업:** 웹Claude 스펙 → 클로드코드 구현 → 대수 커밋. **파생 위젯 1개 · 새 테이블/마이그레이션 없음**(조회만). 기존 `*Today.jsx` 패턴 그대로.
> **배경:** 회원 '이의' 버튼을 빼는 대신(반응형 → 능동형), **오늘 스케줄 잡힌 회원에게 미확인 수업일지가 있으면** 트레이너 '오늘' 탭에 "미확인 수업 확인해주세요"를 띄운다. 회원이 오늘 오니 **그 자리에서 폰으로 확인받게** 유도. (이의 제거로 생기는 "미확인이 방치됨" 구멍을 이게 메운다.)
> **근거(실제 소스):** `appointment`(예약) `docs/migrations/2026-07-19-appointment-record.sql` · `daily_workout_log`/`workout_log_confirmation` · 기존 파생 위젯 `components/views/ReapproachToday.jsx`·`RegisterDueToday.jsx`(같은 패턴·오늘 탭 마운트).

## 1. "미확인 수업" 정의 (회원 게이트와 동일 기준)
한 `daily_workout_log` 로그가 **미확인** = 다음을 모두 만족:
- `coalesce(voided,false)=false` AND `coalesce(source,'')<>'noshow'` (확인 대상인 실수업)
- `session_at < 오늘(KST)` (오늘 수업은 유예 — 회원 게이트와 동일)
- 그 `log_id`에 대한 `workout_log_confirmation` **confirm 행이 없음**

## 2. "오늘 스케줄 회원"
- `appointment` where `start_at ∈ [오늘0시(KST), 내일0시)` AND `status='booked'` → 회원 `user_id` 집합.
- RLS(`auth_read_appointment`)가 이미 **트레이너 본인 담당 + account 스코프**로 좁혀준다(별도 필터 불필요, `.eq("status","booked")`만).

## 3. 위젯 로직 (파생 · 새 저장 0 · `RegisterDueToday` 골격 재사용)
`components/views/UnconfirmedConfirmToday.jsx` (신규):
1. 오늘 booked 예약 조회 → `memberIds`(오늘 오는 회원). 비었으면 렌더 없음.
2. `daily_workout_log`(위 §1 필터, `.in("user_id", memberIds)`) + `workout_log_confirmation`(`result='confirm'`, `.in("member_id", memberIds)`) 조회.
3. 회원별 **미확인 수** = confirm 없는(§1) 로그 수. `>0`인 회원만 목록.
4. 렌더: `ToneCard` + `SectionHeader`("확인 필요" 등) + 회원별 `ListRow`(이름 · "미확인 수업 N건 · 확인 요청") → 탭 시 `onSelect(user_id)` → 그 회원 PT뷰 열림.
- 데모(`!supabase`)·무예약·미확인 0 → `null`(카드 미표시). 라이브 전용 위젯(형제들과 결 동일).
- 정렬: 미확인 많은 순 or 예약 시각(`start_at`) 이른 순. (제안: 예약 시각 순 — 곧 오는 회원부터.)

## 4. 배치 · 톤
- `app/page.jsx` '오늘' 탭의 "오늘의 대상자" 위젯군에 추가(ReapproachToday·RegisterDueToday와 나란히). 같은 파일에서 `members`·`onSelect` prop 전달.
- **톤 제안:** `neutral`(zinc) 또는 `reapproach`(amber · "챙길 것"). 우선순위 red(brand/unclosed)까진 아님 — 대수 선택. (`widgetTone` 역할명 사용.)

## 5. ⚠️ 액션의 성격 (오해 방지)
이 위젯은 **리마인더 + 진입**이다 — 트레이너가 회원 대신 확인할 수 **없다**(확인은 회원 JWT로만). 탭하면 그 회원이 열리고, 트레이너는 (a) 회원에게 "폰에서 확인 눌러주세요" 요청(회원앱 소프트 게이트가 뜸) 하거나 (b) 안 받은 수업이면 **void**(트레이너 수정/삭제 스펙). **위젯 자체는 확인 버튼을 갖지 않는다.**

## 6. 쿼리/성능 규율
- 무필터 대량조회 **아님**(오늘 예약 회원=소수 · `.in(user_id)`) → `fetchAllRows` 불필요.
- ⚠️ `useEffect` deps에 `members` 배열참조 넣지 말 것 → **`memberKey=(members||[]).map(m=>m.id).join(",")`** 패턴(RegisterDueToday·P1-9 정답). 재조회 루프 방지.
- 조회 전용(write 0)이라 교훈1 대상 아님 — 단 로더 `try/catch/finally`로 로딩 가드(P1-8 규율).

## 7. 검증
- 오늘 booked 예약 있는 회원 + 미확인 수업 있음 → 위젯 뜸(회원명·N건). 회원이 확인 → 다음 로드에 그 회원 빠짐/감소.
- 예약 없음/미확인 0 → 안 뜸. 취소·완료 예약은 제외(`status='booked'`만).
- 탭 → 그 회원 PT뷰 열림.

## 8. 파일 지도
- 신규 `components/views/UnconfirmedConfirmToday.jsx`(파생 위젯).
- `app/page.jsx` — 오늘 탭에 마운트(`members`·`onSelect`).
- 마이그레이션 없음(조회만 · RLS 기존 그대로).

> **연결:** 이 위젯이 있으면 회원앱 '이의' 버튼 제거가 안전하다 — 미확인은 이제 트레이너가 오늘 할일에서 능동적으로 챙긴다(반응형 이의 불필요). 이의 제거 결정과 세트로 간주.
